Prerequisites

System Requirements

  • OS: Linux (Ubuntu 18.04+, CentOS 7+, Alpine 3.10+)
  • RAM: 16GB minimum, 32GB+ recommended
  • Storage: 80GB+ free disk space (Docker images ~30–40 GB; model weights ~8–50 GB additional)
  • CPU: 4 cores minimum, 8 cores recommended
  • GPU / VRAM: NVIDIA GPU with CUDA support — required only for self-hosted LLM inference (8 GB VRAM minimum for small quantised models; 24 GB+ recommended). Not required if using a managed cloud LLM provider.

Software Requirements

  • Docker: 20.10+
  • Docker Compose: 2.0+
  • Python: 3.7+ (installer scripts only; platform runs inside Docker)
  • Git: Latest version

Package Deployment

A self-contained deployment package — a Docker Compose configuration plus a small set of install/operations scripts.

1

Download Package

After activating your license, download the enterprise package from your unique link at raghim.com.

# Extract the package
unzip raghim-enterprise-2.0.20.zip
cd raghim-enterprise-2.0.20
2

Run the Installer

Run install.sh, which auto-detects your network configuration, generates a secure .env with generated secrets, pulls the required container images, and starts the stack.

./install.sh
Note: On first run you'll be prompted to review the generated environment configuration before the stack starts.
3

Automated / CI Deployment

For CI/CD or unattended environments, set your configuration via environment variables before running — the same script skips interactive prompts when it detects a non-interactive shell.

# Automated deployment (non-interactive)
./install.sh
Warning: Non-interactive deployment still generates strong random secrets, but review the resulting .env before exposing the deployment to production traffic.

Licensing & Activation

A new deployment starts in a time-limited evaluation trial; a previously-activated license that lapses gets a separate renewal grace period. The application requires an activated license once its trial or grace window ends.

How It Works

  • A brand-new, never-activated deployment runs on a short evaluation trial with no configuration required — once it ends without an activated license, the application requires activation before it will continue serving requests.
  • A deployment that was previously activated and whose license has since lapsed gets a separate, short renewal grace period instead of a new trial.
  • Activation works in fully offline / air-gapped environments: the deployment generates a system-specific activation request, which you exchange for a signed license file — no persistent internet connection is required for ongoing operation.

Getting a License

Activate or purchase a license at raghim.com, or contact sales@raghim.com. The admin dashboard shows your current license status and remaining trial/grace time at any point.

Cloud Deployment

Deploy on cloud platforms with external GPU support for enhanced performance.

Self-Hosted GPU Deployment

1

Provision a GPU-Enabled Host

  • Any machine with an NVIDIA GPU — local hardware or a rented cloud GPU instance — running the standard deployment package
  • Choose a recent Linux image with the NVIDIA Docker runtime installed
  • Configure SSH key-based access
2

Start the Self-Hosted Inference Service

The self-hosted language-model service is an optional profile on the same deployment package — no separate download or manual scripts required.

# Enable the GPU inference profile
docker compose --profile gpu up -d

Configuration

Configure your deployment using environment variables and configuration files.

Environment Variables

Variable Description Default
JWT_SECRET_KEY JWT secret for authentication Generated
POSTGRES_PASSWORD Database password Generated
REDIS_PASSWORD Redis cache password Generated
GPU_ENABLED Enable GPU acceleration true
FRONTEND_URL Frontend access URL https://<app-domain>
API_URL Backend API URL https://<api-domain>
WIDGET_DOMAINS Widget embedding domains Empty

Model Configuration

# Default models (override in .env)
EMBEDDING_MODEL=<multilingual-embedding-default>
VLLM_MODEL=<self-hosted-model-default>
VLLM_BASE_URL=<self-hosted-inference-url>

# LLM_PROVIDER supports managed cloud providers (OpenAI, Anthropic) or self-hosted vLLM
LLM_PROVIDER=<approved-provider>

# Token and reasoning tuning (when LLM_PROVIDER=openai)
OPENAI_TIER_HYBRID_TOKENS=<profile-default>
OPENAI_RAG_REASONING_EFFORT=<policy-default>

Optional & Bundled Services

Monitoring Stack

The deployment package includes an optional monitoring stack (Prometheus, Grafana, and metric exporters) that can be enabled via a Docker Compose profile. These services are disabled by default to conserve resources on smaller deployments.

# Enable monitoring stack (Prometheus + Grafana + exporters)
docker compose --profile monitoring up -d

# Check monitoring services
docker ps | grep -E "raghim-prometheus|raghim-grafana"
Resource note: The monitoring stack adds approximately 2–4 GB RAM overhead. Ensure your host has sufficient capacity before enabling.

Workflow Connector Services

The platform includes bundled workflow automation and connector services that start automatically alongside the core stack. These power the agent flow, MCP tool execution, and external integration features. No additional configuration is required for basic operation; connector-specific settings are managed through the Admin interface.

# Verify all services including connectors are running
docker compose ps

# Check connector service logs if agent flows fail
docker compose logs --tail=50

Common Issues

Connection Refused

Symptoms: "This site can't be reached" or "ERR_CONNECTION_REFUSED"

Solutions:

  • Check if containers are running:
  • Verify firewall settings (ports 80, 443)
  • Use external IP for VM deployments
  • Test from server:

GPU Not Detected

Symptoms: Slow AI responses, GPU not utilized

Solutions:

  • Install NVIDIA Docker runtime
  • Set LLM_PROVIDER=<approved-provider> in .env
  • Check CUDA installation
  • Verify GPU availability: nvidia-smi

Memory Issues

Symptoms: Out of memory errors, slow performance

Solutions:

  • Increase system RAM
  • Reduce OPENAI_TIER_HYBRID_TOKENS
  • Set OPENAI_RAG_REASONING_EFFORT to none or low
  • Use smaller models

Database Connection

Symptoms: Database connection errors or vector search failures

Solutions:

  • Check PostgreSQL container status: docker logs raghim-postgres
  • Verify database credentials in .env
  • Check network connectivity between containers
  • Review database logs: docker ps | grep raghim-postgres
  • Note: pgvector is integrated into PostgreSQL — no separate vector database container or port is used
